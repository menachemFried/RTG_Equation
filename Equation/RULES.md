# Antigravity IDE AI Agent Instructions for Eclipse Managed Build Project

## Core Architecture and Constraints

1. **Primary IDE Authority:** This workspace is natively managed by Eclipse CDT employing a strictly GUI-based "Managed Build System". Eclipse is the sole source of truth for build dependencies.
2. **Build System Freeze:** The Makefiles located in the Debug/ and Release/ directories are automatically generated by the Eclipse CDT internal builder. DO NOT attempt to edit these Makefiles manually under any circumstances.
3. **No CMake Allowed:** DO NOT attempt to scaffold, initialize, or write alternative build systems such as CMakeLists.txt, Makefile (in the root directory), or Bazel configuration files. The build architecture is immutable from this interface.
4. **Workspace Segregation:** Files such as .cproject, .project, and the contents of the .settings/ folder dictate the Eclipse project structure. They are strictly READ-ONLY. Do not read from them to infer project structure, and never modify them.

## Workflow and Execution Rules

- **Compilation Protocols:** To compile the project or test structural code changes, exclusively utilize the predefined VS Code tasks configured in .vscode/tasks.json (e.g., executing the task Eclipse: Build Debug). Never run raw gcc, g++, or make commands sequentially on individual files in the terminal.
- **Dependencies & Includes Management:** Code completion and syntax validation are powered by the compile_commands.json database. If you create a new source (.c, .cpp) or header (.h) file, recognize that you lack the clearance to add it to the build system directly. You must explicitly inform the human operator to open the Eclipse UI to synchronize the workspace, re-generate the Makefiles, and subsequently update the compile_commands.json.
- **Debugging Operations:** When diagnosing runtime faults, rely strictly on the provided launch.json configuration. Evaluate the standard output and standard error from the Eclipse: Build Debug task prior to initiating any runtime debugging.
